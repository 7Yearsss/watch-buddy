## 怎么拿：明细在手机上算，只上传结果

| 层 | 在手机上读（不上传） | 上传 | 用途 | 阶段 |
|---|---|---|---|---|
| 1. 每日汇总 | 步数、站立、活动能量、爬楼 | 每天总数 | 草、火、地面回响 | MVP |
| 2. 手机上算的特征 | 心率明细、睡眠各阶段、HRV 明细 | 高心率区间分钟、深睡比例、入睡时间、夜间 HRV 平均、静息心率 | 电、暗影、水回响 | MVP |
| 3. 事件摘要 | 每次运动记录 | 每次一行：类型、开始时间、时长、距离、平均心率（不含 GPS） | AI 说出具体事件（"周三晚上那 5 公里"），对战回放讲具体哪天 | MVP |
| 4. 特殊功能 | 加速度传感器 | 只传峰值时间点 | 碰手腕 | 第三步 |

- **防作弊：** 带"手动录入"标记的记录不计入回响；单日封顶。
- **步数去重：** 用 HealthKit 统计查询（自动合并 iPhone 和手表），不自己相加。
- **有数据的日子（2026-11-21 改，决策第 74 条）：** 手表白天戴满约 4 小时，或者任何设备（包括 iPhone）当天步数 ≥ 1,500，就算"有数据的日子"，照常结算。**不看夜里**：大多数人晚上给手表充电（用户问卷里戴表睡觉的只有约 11–14%），原来"夜里没有心率就算没戴"会让这些人的宠物完全不长。一整天都没有数据，宠物"在睡觉"，不扣任何东西。
- **晚上没戴（没有睡眠数据）：** 睡眠这一项**按"普通的一晚"算**（水的回响记 0.5，用于成长、恢复属性和状态加成）。戴表睡觉的人睡得好能拿更多，睡得不好也不会低于"普通的一晚"，所以**戴表睡觉永远不吃亏、只会多拿一点**。野怪遭遇仍看真实数据，但水系和暗影野怪有保底权重（倾向按至少 0.6 算），保证图鉴收得齐。
- **睡眠从哪来：** Apple Watch 的睡眠记录，或者写进健康数据的第三方设备和 App（如智能戒指、睡眠 App）。iOS 18 之后 iPhone 单独记录的"在床上"时间不可靠，不作为来源。
- **早上开奖什么时候：** 戴表睡的人按醒来推送；晚上充电的人按"每天第一次戴上手表"或平时开始活动的时间推送（从历史数据学）。
- **轻轻鼓励戴表睡觉：** 宠物只在"陪你睡了一晚"的第二天讲梦境日记；新手引导里提一句"早上洗澡时充一会儿电，晚上就能陪它睡"。不催、不扣。
- **后台同步：** HealthKit 后台通知 → iPhone 自动计算并上传，不用打开 App 早上也能"开奖"。
- **透明页：** App 内列出原样上传的数据 + "删除全部数据"按钮。

## 合规

- **苹果审核：** 健康数据只能用于 App 自己的功能，不能用于广告、营销或卖给第三方；必须有隐私政策；授权弹窗写清用途；不往"健康"App 写假数据（我们只读不写）。
- **第三方 AI：** 把健康汇总发给第三方大模型前，要单独弹窗告知并获得同意。苹果本地的 Foundation Models 不算第三方。
- **最小必要：** 只收集功能用得上的数据；以后有功能需要明细，再补隐私政策并单独征得同意。
- **国区：** MVP 先只上海外区。国区要处理游戏版号（带内购的游戏需要，个人开发者基本拿不到，最大风险）、AI 备案、健康数据属于敏感个人信息需单独同意、服务器在海外时的数据出境。

## 两层结构：成长值 + 状态

- **成长值（永久）：** 只涨不跌，代表"养了多久、多用心"，决定基础属性，同时填进化进度条。
- **状态（临时，只加不减）：** 由最近 3 天的"当天质量"（0.5 × 睡眠回响 + 0.5 × 最高的运动回响，负数按 0 算）平均决定，是 1.00–1.25 的系数，**只乘在对战伤害上**（乘在全部属性上会叠加成约 +50% 战斗力，见 [04 对战](04-对战.md)）。睡得好、动得多就有加成；偷懒只是没加成，永远不低于正常值。

## 个人基线

- 每项指标取**最近 28 天的中位数**作为基线（中位数比平均数抗异常值，比如偶尔一次马拉松）。
- 首次打开直接读取 HealthKit 过去 28 天历史作为基线，大多数用户第一天就有真实基线。
- 历史数据不够 7 天时，用人群默认值和自己的数据按天数混合：`基线 = (n×自己中位数 + (7−n)×默认值) / 7`。
- 基线有下限（比如步数不低于 2,000），防止"基线极低，随便动动就暴涨"。

## 每日回响

对每项指标算一个跟自己比的分数：

```
比值 r = 今天 / 基线
分数 s = clamp((r − 1) / 0.5, −1, +1)      // 比平时多 50% 就满分，少 50% 就最低
```

例外（不是越多越好）：
- **睡眠：** 用绝对区间打分，7–9 小时满分，偏离越多越低。再加"入睡时间跟平时差多少"的规律分。
- **静息心率：** 越低越好，方向反过来。
- **HRV：** 跟自己基线比，越高越好，只看 7 天平均（单日波动太大）。

每种属性的回响 = 对应数据分数的加权和：

| 回响 | 用到的数据和权重 |
|---|---|
| 草 | 步数 0.7、站立小时 0.3 |
| 水 | 睡眠时长分 0.6、入睡时间规律分 0.4 |
| 暗影 | 深睡比例 0.6、夜间 HRV 0.4 |
| 火 | 活动能量 0.6、高强度训练分钟 0.4 |
| 战斗 | 力量训练分钟 1.0 |
| 飞行 | 有氧运动分钟 0.7、步行跑步距离 0.3 |
| 电 | 高心率区间分钟 0.7、间歇训练分钟 0.3 |
| 地面 | 最近 7 天有活动的天数 0.6、爬楼层数 0.4 |

**稀疏的运动指标用 7 天滚动总量：** 有氧、力量、高强度、间歇、高心率区间、距离这些不是每天都有，如果按"今天 vs 平时"算，休息日会被当成"比平时差"。所以这些指标用"包括今天在内最近 7 天的总量"对比"基线的每周总量"（基线 = 过去 28 天总量换算成每周）。

**成长值每天增加：** `成长值 += 10 + 10 × （最高 3 种回响的平均，负数按 0 算）`。只要戴着就有保底 10 点，在几个方面都比平时好才能翻倍（只取最高 1 种时，随机波动几乎总让某项很高，见 [模拟结果](../SIMULATION.md)）。模拟中日均约 15。每天最多 20 点，再加单项数据封顶（如步数 6 万）防止刷数据。

**五项属性各自的成长：** 每天 `2 + 2 × max(0, 该属性来源回响里最高的那个)`。

## 生活方式倾向（用于进化分支和野怪）

回响是"跟自己比"，适合衡量努力；但进化形态代表"你是什么样的人"，要用绝对标准。每种属性的倾向是 0–1，看一段时间（进化看 21 天）的平均水平对照健康指南：

| 倾向 | 计算（每项封顶 1） | 参考标准 |
|---|---|---|
| 草 | 0.7 × 日均步数 / 8000 + 0.3 × 日均站立 / 12 小时 | 常用的每日步数目标 |
| 水 | 0.6 × 睡眠得分（5 小时及以下为 0，7 小时及以上为 1）+ 0.4 × 入睡时间规律的夜晚占比（离中位数 60 分钟内） | 成人每晚至少 7 小时 |
| 暗影 | 平均深睡比例 / 15% | 健康成人深睡约占 13–23% |
| 火 | 0.6 × 日均活动能量 / 500 千卡 + 0.4 × 每周高强度 / 75 分钟 | WHO：每周 75 分钟高强度 |
| 战斗 | 每周力量训练 / 60 分钟 | WHO：每周至少 2 天力量训练 |
| 飞行 | 0.7 × 每周有氧 / 150 分钟 + 0.3 × 每周距离 / 15 公里 | WHO：每周 150 分钟中等强度 |
| 电 | 每周高心率区间 / 75 分钟 | 同 WHO 高强度 |
| 地面 | 0.6 × 每周活跃天数 / 5 + 0.4 × 日均爬楼 / 10 层 | — |

- 只用戴了手表的日子算平均，没戴不拉低。
- 所有参考值都在 `packages/engine/src/config.ts` 里，可以用批量模拟再调。

## 五项战斗属性

| 属性 | 来自哪种回响 |
|---|---|
| 体力 | 草 |
| 恢复 | 水、暗影 |
| 攻击 | 火、战斗 |
| 速度 | 飞行、电 |
| 防御 | 地面 |

每项属性有自己的成长值，按对应回响分配。物种和属性决定基础值的分布（比如飞行系速度高、火系攻击高），健康数据决定在这个分布上长多少：

```
基础属性 = 物种基础值 × (1 + 0.5 × log2(1 + 成长值 / 300))
```

用对数是为了边际递减：养 3 个月的宠物比养 1 个月的强，但不会强 10 倍。

## 心情

只影响 AI 说话和动画，不影响战斗：
- 开心：昨晚睡够 + 今天有活动
- 犯困：睡眠分低
- 无聊：连续两天活动明显低于平时
- 生病（小概率、温和）：连续 3 天以上睡眠很差，需要"好好睡一觉"才好

## 首次打开：授权流程（原型已实现）

**参考：** HealthKit 的授权弹窗是系统固定的界面（每种数据一个开关），App 改不了，所以弹窗前的"说明页"是唯一能解释"为什么要这些数据"的地方；审核也要求界面上明确说明用了 HealthKit。说明页通常能提高同意率，用户更吃"对我有什么直接好处"。HealthKit 不会告诉 App 用户拒绝了读取，只是读不到数据。（[UX Planet](https://uxplanet.org/getting-to-yes-best-practices-for-ios-permissions-dialogs-9d62892142cc)、[Adjust](https://www.adjust.com/blog/getting-the-opt-in/)、[Appcues](https://www.appcues.com/product-adoption-academy/mobile-app-onboarding-101/priming-users-to-grant-mobile-apps-permission)、[Apple 论坛 2.5.1](https://developer.apple.com/forums/thread/813897)；没找到 HealthKit 专门的同意率数据，需要自己测）

**流程（3 步，约 30 秒）：**
1. **选蛋**：三颗蛋各写一句"谁会长得更快"，并说明三种最终都能进化成任何形态。
2. **说明页**：活动 / 睡眠 / 心脏三组，每组一句"决定它的什么"；三条承诺：只读不写、每天只传一行汇总且不传位置、永远跟自己比。主按钮"好，去授权"，次按钮"先不授权，直接孵化"。
3. **读取**：蛋在晃，读到的事实一行行出现（"读到了 25 天的数据""平均每天走 7600 步"……），然后播孵化演出。

**拒绝也能玩**：没有数据就按大众默认值孵化，宠物说"从今天开始吧"，读取页提示"以后在设置里打开，它就能长得更快"。不卡住、不反复弹。

## 运动后的反应（原型已实现）

**能做到什么（待在真机上验证）：** 第三方 App 看不到别的 App（包括 Apple 自带的"体能训练"）正在进行的运动，Apple 的"自动检测运动"只给用户弹提示，没有开放给开发者。我们能做的是：运动**保存进健康数据之后**，用 HealthKit 的后台推送（observer query + background delivery）被叫醒，通常要等几分钟。实时陪跑只有在**用户在我们自己的 App 里开始运动**时才行（自己建 workout session），MVP 不做。（[Apple 论坛：自动检测](https://developer.apple.com/forums/thread/657111)、[startWatchApp 文档](https://developer.apple.com/tutorials/data/documentation/healthkit/hkhealthstore/startwatchapp(with:completion:).md)、[running workout sessions](https://developer.apple.com/documentation/healthkit/running-workout-sessions.md)；后台推送的具体延迟没查到权威数字，要真机测）

**做法：**
- 运动保存后，下次抬腕时宠物在欢呼："有氧 30 分钟！辛苦啦"，配一次 `success` 震动（算进每天 ≤3 次）。
- "今天"页写"刚运动完！明早速度会涨"。**不当场给数字**，成长照旧第二天早上一起结算，保住"早上开奖"的期待。
- 不推送通知。
