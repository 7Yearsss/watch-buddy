> 相关：[01 核心玩法](01-核心玩法.md) · [02 宠物与进化](02-宠物与进化.md) · [决策记录](../DECISIONS.md)

## 0. 两条总准则（所有界面改动都要过）

### 0.1 体验：复杂留给系统，不留给用户

用户体验至高无上。每做或改一处界面，都逐条问：

- **系统能判断的，不留给用户**：能从数据、时间、上下文推出来的，不让人选、不让人填。
- **此刻没用的，就不出现**：跟当前状态无关的按钮、提示、数字一律藏起来。
- **能替人做的，就直接做**：能自动完成的不要求人点"确认"。
- **同一件事，处处一样**：同一个概念用同一个词、同一个图标、同一种操作，手表、手机、网站一致。
- **按下去有回应，再按能收回**：每个操作立刻有反馈；能撤销的给撤销，开关再按一次就回去。
- **不打断人手上的事**：不弹窗抢焦点，提示放在不挡路的地方，演出可跳过。
- **常用的好做，会丢东西的难误碰**：高频操作放手边、一步到位；删除、放生、重置这类会丢东西的操作远离常用区，要二次确认或可撤销。
- **界面自己说明自己**：不靠说明文字和教程，看一眼就知道是什么、能做什么、做完会怎样。

### 0.2 动效：细腻、丝滑，在解释发生了什么

不按部件找，按**状态变化**找：任何东西出现、消失、移动、变大小、换内容、换图标、数值跳动、按下、悬停、加载、完成、出错，都问一句——这个变化用户看得懂吗？是突然跳过去的，还是有来有去、交代清楚了？大到页面切换，小到一个图标、一个数字、一个勾，都在范围里。

- **解释，不装饰**：动效交代东西从哪来、到哪去、和什么有关。
- **一套语言**：同一类变化用同一种曲线和节奏，统一用项目里已有的动效变量，不每处自己发明。
- **克制**：快、轻、不抢戏；用户反复做的操作更快，宁可少动也不乱动。
- **跟手、可打断**：拖动和调整大小直接跟手；动画进行中再次操作能自然接上，不等它播完、不跳回起点。
- **不付性能代价**：只动 transform / opacity 等必要属性，长内容里也稳定满帧；交付前自己量过。
- **不引入新问题**：不抖、不闪、不重排、不溢出；尊重系统的"减少动态效果"（见第 4 节辅助功能）。
- **处处成立**：手机、窄窗口、宽屏、深浅色都要检查。

### 0.3 怎么验收

改完亲手用一遍（真点、真拖、打断、开减少动态效果、换窄屏和深色），再自己审查一遍改动，两条准则逐条对照，没问题再合并。

## 1. 让因果看得见：早晨卡片

**参考：** Pokémon Sleep 把一晚的睡眠压成一个分数，第二天早上直接变成"来了几只宝可梦"；Pikmin Bloom 每天自动生成一段"一天的回顾"动画（走了多少步、去了哪、种了多少花）。共同点是：**一个总结、一个结果，玩家不用读数字**。

**规则：** 产品主体是手表，所以早晨卡片**先在手表上播精简版**，手机上看完整版。

**手表版（主）**：早上第一次抬腕时自动播，3 屏，每屏约 1 秒，点一下跳到下一屏，可以整段跳过：
1. **昨晚**：睡姿图标 + 一个时长（"7 时 20 分"）。
2. **最突出的一件事**：一句话 + 结果（"跑步 40 分钟 → 速度 +3"）。
3. **成长**：进度环涨上去，有野怪或小惊喜时在环上冒一个"！"，提示"去手机看看"。
- 3 屏合计最多 3 个数字；只在开始时震一次（见第 4 节）。

**手机版（完整）**：打开手机 App 时播（约 5 秒，可点击跳过），分 4 步：
  1. **昨晚**：睡了多久 + 一个图标（好 / 一般 / 少）。
  2. **昨天**：最多挑 **2 件**最突出的事，用人话 + 结果，例如"跑步 40 分钟 → 速度 +3""比平时早睡了 30 分钟 → 恢复 +2"。永远跟自己比（"比平时多 30%"），不报绝对排名。
  3. **成长**：今天 +N 成长值，进度条动画涨上去。
  4. **惊喜**：野怪或当天的小惊喜（见第 2 节）。
- 整张卡片里**最多出现 3 个数字**，其余用图标和形容词。
- 没什么亮点的日子也要找一件小事说（"你今天站起来活动了 11 个小时"），不能出现空卡片；但**不批评**（"只加不减"）。
- 手表上看过的部分，手机上快速带过（每步 0.5 秒），不重复等待。

## 2. 没有大奖的日子：每日小惊喜

**参考：** Finch 的小鸟去冒险、回来跟你讲故事，奖励的种类和颜色都会变；动物森友会靠"可预期的小收获 + 偶尔的意外"（比如飘来的气球）。研究和评论都指出：**可预期的小胜利**和**偶尔的惊喜**一样重要。

**规则：** 约 70% 的早晨没有野怪，这些日子从下面的池子里**抽一件**（3 天内不重复同一种）：

| 小惊喜 | 例子 | 作用 |
|---|---|---|
| 梦境日记 | "我梦见自己在云上跑步……一定是因为你昨天跑了 5 公里" | 用故事把数据讲出来，最有陪伴感。**只在戴表睡觉的第二天出现**：把"陪它睡"变成额外内容，不是门槛 |
| 捡到小东西 | 按属性掉落收藏品：草系叶子、水系贝壳、火系火石……攒进"收藏册" | 可预期的小收获，第二条收集线 |
| 野怪足迹 | "附近有电系足迹……多做间歇训练，说不定能遇到它" | 告诉玩家怎么用健康行为去找想要的野怪 |
| 数据小发现 | "你这周平均入睡比上周早了 20 分钟！" | 让玩家看到自己的变化 |
| 学会新动作 | 宠物学会一个新的待机动作（伸懒腰、转圈） | 宠物在"长大"的证据 |
| 流星雨 | "昨晚有流星雨，我许了个愿：明天遇到野怪的机会翻倍！" | 第二天遇怪概率 ×2 |
| 迷路的野怪 | "有只迷路的野怪来借宿一晚……明早它会来找你比试" | 第二天必定遇到一只还没收服的野怪 |
| 藏宝图 | "我捡到了一张藏宝图！3 天后宝箱就能打开" | 3 天后开出一件只有宝箱里才有的收藏品 + 成长值 10；同时最多一张 |
| 明天的天气 | "明天会下雨，水系野怪会多出来哦"（下雨 / 大晴天 / 刮风 / 雷雨） | 第二天野怪偏向对应属性（水 / 火 / 飞行 / 电） |

- 每天早上**一定有一件事**，所以每天都值得打开；大奖（野怪、进化）照旧低概率。
- 后 4 种"改变明天"的事件权重较低，让它们保持像新闻；它们让玩家有理由期待第二天。
- 收藏册、足迹提示都不给战斗力。

### 每日小心愿（可选任务）

宠物有时会用自己的口吻提一个小心愿，例如"今天想多出去走走，我们走到 8,600 步好不好？"。

| 规则 | 说明 |
|---|---|
| 频率 | 约 70% 的早上有一个，每天最多一个；3 天内不重复同一种 |
| 种类 | 多走走（步数）、早点睡（入睡时间）、睡够（睡眠时长）、动一动（运动分钟）、爬爬楼（层数）；孵化当晚固定是"戴着手表睡一晚" |
| 难度 | 按自己最近 14 天的中位数略提高：步数 ×1.1（至少多 500），早睡 15 分钟，多睡 15 分钟，运动多 5 分钟（至少 15），爬楼多 2 层（至少 5）；不足 5 天数据的项目不出 |
| 奖励 | 第二天早上成长值 +6；其中约 30% 还会让当天遇怪概率翻倍 |
| 没做到 | 什么都不扣，宠物说"没实现也没关系，能陪着你就很开心" |
| 显示 | 早晨卡片最后一步、手机"今天"页的心愿卡、手表瞄一眼页的一行小字；手表气泡在没别的事时显示心愿 |

模拟（6 种生活方式各 10 人 × 60 天，人物不会为心愿改变行为）：什么都不做也有 21–36% 的心愿自然实现，所以稍微努力就能做到。第一次进化平均提前约 1 天（10.8 天对 11.7 天），在可接受范围。代码：`packages/game/src/wish.ts`。

### 以后再加的随机内容

- **每周挑战**（第二步）：每周一公布一个主题，比如"爬楼周""早睡周"，达标给周 Boss 加成或开一个宝箱。需要服务器下发配置。
- **限时活动**（第三步）：节日或每月一次，限定配饰、限定野怪、好友合作任务。

## 3. 大事件演出

**参考：**
- 抽卡和开卡包的设计经验：重点在揭晓之前的"期待"，颜色是稀有度的暗号（金光 = 最稀有），可以先停一拍再揭晓；太快显得廉价，太慢让人走神。很多游戏跳过铺垫，直接揭晓，浪费了戏剧性。
- 宝可梦的进化：整体发光、看不清具体变形过程，用光和剪影带过。

**通用规则：**
- 每个演出 **≤ 6 秒**；第一次完整播放，之后同类演出可以点击跳过或自动缩短。
- **稀有度暗号不用颜色**：9 个属性的主色已经占满了绿、蓝、紫、黄、橙，如果再用"绿 = 不普通、蓝 = 稀有"，草系宠物发绿光会分不清是稀有度还是属性。所以稀有度用**星数 + 光的形态**表示，光一律是白色（不带色相），只有传说用彩虹色（没有属性是彩虹色）：

| 稀有度 | 星数 | 光的形态 |
|---|---|---|
| 普通 | ★ | 不发光 |
| 不普通 | ★★ | 脚下一圈白色微光 |
| 稀有 | ★★★ | 白色光环 + 2–3 个闪点 |
| 史诗 | ★★★★ | 光环 + 闪点绕身体转圈，慢慢闪 |
| 传说 | ★★★★★ | 彩虹流光光环 + 星星粒子 |

  所有演出、卡片边框、图鉴都用这一套。属性色只用在宠物身体和技能特效上。
- **只往上骗，不往下骗**：可以"先亮到 3 颗星，停一拍，再加第 4 颗"，但绝不先给好的再收回，避免失望（"只加不减"）。
- 演出结束停在一张"结果卡"上（新形态、名字、变化了什么），方便截图分享。

| 演出 | 时长 | 分镜 |
|---|---|---|
| 孵化 | 约 10 秒 | 蛋晃 3 次，间隔越来越短 → 出现裂缝 → 白光一闪 → 剪影（已经能看出体型、耳朵、尾巴的轮廓）→ 上色、弹跳一下 → **基因一项项揭晓**：眼睛睁开 → 耳朵 / 尾巴抖一下 → 花纹浮现，每项弹出一个小标签（"卷焰耳 · 33%"），稀有基因多一道闪光 → 基因卡 + 名字和性格（"我是佛系的，请多指教"）。可以点击跳过直接看基因卡（见 [02](02-宠物与进化.md) 基因） |
| 进化 | 约 5 秒 | 宠物开始发光（光的形态 = 当前稀有度）→ 新旧形态的剪影来回切换，越来越快 → 白光 → 新形态登场，晃一下 → 结果卡（新形态名、属性变化、稀有度是否提升） |
| 收服 | 约 3 秒 | 战斗胜利 → 野怪变成光球飞进图鉴 → 盖一个"新收录"印章；没收服时野怪跑掉，图鉴里亮起一个剪影 |
| 稀有度提升 | 约 3 秒 | 星星一颗颗点亮、光环一级级变强，停在新等级前多停一拍 → 新的外观（配饰、眼睛、特效）出现 |
| 周 Boss 胜利 | 约 2 秒 | 胜利姿势 + 彩带；失败时只显示宠物喘气，没有"失败"大字 |

### 战斗回放（原型已实现）

参考：打击感的通用经验是把几种小反馈在约 100 毫秒内叠在一起，但**同一种信息只用一种信号**（白闪、橙数字、红血条同时表示"受伤"反而乱）；震屏最容易被滥用，只该给重要的一击；伤害数字既是反馈也是信息，要克制（[eastondev](https://eastondev.com/blog/en/posts/dev/20260521-game-feedback-feel/)、[bugnet: 伤害数字](https://bugnet.io/blog/how-to-build-a-damage-number-system)、[wayline: juice 的问题](https://wayline.io/blog/the-juice-problem-how-exaggerated-feedback-is-harming-game-design)）。这些多是开发者经验文章，没有专门针对自动战斗的研究。

- 双方宠物站在舞台两边（对手面朝左），头顶名字和血条。
- 每一步一个飘字，落在**被打的那一方**：普通白色、克制黄色更大（上面写"效果拔群"）、被抵抗灰色更小、暴击最大；回血绿色；护盾、变慢、闪避用浅蓝小字。
- 只有暴击和大招才震屏；减弱动态效果时不震、飘字不动。
- 1× / 2× 倍速，"跳到结果"，结束后可以"再看一遍"。
- 结束横幅：胜利 / 平局 / "差一点！明天再来" + 回合数 + **关键一击**（全场最高伤害是谁、哪个技能、为什么高）。
- 文字记录折叠在下面。

### 分享图（原型已实现）

参考：Spotify Wrapped 每页都是 9:16 竖图，正好是 Stories 的尺寸，用户不用裁剪；分享卡要有一个能"炫"的大字，角落放 App 名字（被转发没链接时也知道出处）；私人数据默认不放（[Design Breadcrumbs](https://designbreadcrumbs.beehiiv.com/p/wrapped-by-design)、[NoGood](https://nogood.io/2025/01/20/spotify-wrapped-marketing-strategy/)、[分享卡设计指南](https://www.skills.sh/khadinakbarlabs/expo-mobile-app-builder/design-shareable-result-card)，多为设计博客，传播数据未经核实）。

- 1080×1920，三种：**我的宠物**（"成长体"/"成熟体·飞行"）、**最近一次 Boss**（"打赢了 Boss！"+ 关键一击）、**图鉴**（"收集了 14 只"）。
- 属性主色的像素渐变背景，宠物放大 15 倍居中，开心表情。
- **默认不带任何健康数字**；勾选"加上我的健康数据"才加一行（如"这周走了 62,812 步"）。
- 右下角 "Pulseling · 跟着你的健康长大"。

## 4. 手表上的动效和震动

**参考：** Apple 的设计规范要求震动的强弱和节奏跟画面动画匹配，不要滥用；手表只能用系统预设的几种震动，每种都有固定含义，要按含义使用。

| 时刻 | 手表画面（≤ 1 秒） | 震动 |
|---|---|---|
| 早晨卡片（第一次抬腕） | 3 屏精简卡片（见第 1 节） | `notification`（系统通知自带），整段只震这一次 |
| 点一下宠物 | 开心表情 + 爱心 | `click` |
| 进度满了、可以进化 | 宠物发光 + "！" | `directionUp` |
| 收服野怪 | 光球飞入 | `success` |
| 孵化、进化开始 / 完成 | 演出开始 / 结束 | `start` / `success` |
| 周 Boss 失败、偷懒 | 宠物喘气 / 犯困 | **不震动**（不用 `failure`，符合"只加不减"） |

- 每天由我们主动触发的震动 ≤ 3 次。
- **常亮模式**（手腕放下时）：只显示一张静止的睡姿图，用暗色调色板，不播放动画，省电。
- 手表上的单个动画都要短于 1 秒（早晨卡片是 3 个 1 秒的屏，可点击跳过）；孵化、进化这类长演出只在手机上播，手表只给一个"去手机看看"的提示。

### 表盘小组件、智能叠放和通知

参考：watchOS 9 起表盘小组件统一成 WidgetKit 的 4 种：圆形、矩形、单行、角落（[WWDC22 10050](https://www.wwdcnotes.com/notes/wwdc22/10050)、[WWDC22 10051](https://developer.apple.com/videos/play/wwdc2022/10051/)）；智能叠放靠"相关度"决定哪张卡片浮上来（[WWDC23 10029](https://developer.apple.com/videos/play/wwdc2023/10029/)）。推送文案的通用经验：越短越清楚越好（表现最好的多在 25 字符以内），模糊的话没人花时间猜；滥用紧迫感会让人直接关掉全部通知（[Braze](https://www.braze.com/resources/articles/write-push-notification-copy.md)、[Appbot 2026](https://appbot.co/blog/app-push-notifications-2026-best-practices/)）。Duolingo 的内疚式通知有效但被批评把重点从学习变成了连胜（[Duolingo 博客](https://blog.duolingo.com/copy-testing-experiments)、[webdesignerdepot](https://webdesignerdepot.com/the-art-of-duolingo-notifications-the-subtle-manipulation-of-language-learners/)）。

| 小组件 | 放什么 |
|---|---|
| 圆形 | 进化进度环 + 宠物头像 |
| 矩形 | 头像 + 一句话 + 进化进度 + Boss 倒计时 |
| 单行 | 纯文字："进化 32% · Boss 2天"（只能放文字和系统图标） |
| 角落 | 弧形进度条 + 小头像 |

- **智能叠放**：可以进化（1.0）> Boss 日上午（0.9）> 早上 6–10 点有新卡片（0.8）> 晚上 21 点后"该睡啦"（0.4，只在叠放里，不推送）> 其他（0.1，不打扰）。
- **通知**：
  - 每天最多 **1 条**早上的通知，挑最重要的一件事：可以进化 > 新收服 > Boss 结果 > 周信 > 遇到野怪 > 小惊喜。
  - 宠物第一人称，**≤ 25 个字**，必须具体（"这周早睡了 20 分钟！"，不说"发现了一件事"）。
  - 不提连胜、不让人内疚；Boss 输了也不说"失败"。
  - 两天以上没打开 App 就停掉每日通知；离开第 3 天、第 7 天各发一条温柔的（"我梦见你了"），之后不再发。
  - 分 4 个开关：早上开奖、进化和收服、好友（默认关）、很久没见。

### 手表 App 的页面

参考：watchOS 10 起，Apple 建议多页 App 用**竖向翻页**，用表冠上下切换，页码点在表冠旁边；可滚动的内容尽量放在最后一页；所有操作既能用表冠也能用触摸完成。（[Digital Crown 规范](https://developer.apple.com/design/human-interface-guidelines/digital-crown)、[WWDC23 10031](https://developer.apple.com/videos/play/wwdc2023/10031)、[WWDC23 10138](https://developer.apple.com/videos/play/wwdc2023/10138)）

| 页 | 内容 | 操作 |
|---|---|---|
| 1 宠物 | 宠物 + 一句话气泡 + “！” | 点宠物：开心 + 说话 |
| 2 今天 | 进化环、昨天 +N、今天发生的一件事、Boss 倒计时 | 只看，2 秒读完 |
| 3 对战 | 好友列表（可滚动，放最后一页） | 点好友 → 蓄力条 → 点一下 → 结果；回放在手机上 |

- 早晨卡片、演出播放时不能翻页；常亮模式只显示时间和睡姿。

### 一天的作息（原型已实现）

参考：拓麻歌子的睡觉时间由孵化时设的时钟决定，早期机型要玩家手动关灯，后来改成自动关灯；不同阶段睡觉时间不同（[MakeUseOf](https://www.makeuseof.com/tag/tamagotchi-keep-alive/)、[TV Tropes](https://www.tvtropes.org/pmwiki/pmwiki.php/Toys/Tamagotchi)、[TamaWeb](https://samandev.itch.io/tamaweb/devlog/781915/content-update-7)）。

- **它跟着你的作息**：睡觉和起床时间取你最近 14 晚的中位数（例如 23:44 睡、06:43 醒），不是固定时钟。
- 四个时段：**快睡觉了**（睡前 1 小时，宠物犯困，气泡"快到睡觉时间啦"）→ **睡着了**（画面变暗，宠物睡觉）→ **刚起床**（起床后 90 分钟，表盘带一点晨光）→ **白天**。
- **自动关灯**，不需要照顾；熬夜不扣任何东西。睡着时点它不会被吵醒，只小声说"zzz…（你也早点睡）"。
- 原型右侧面板可以拖"模拟时间"试不同时段。

### 辅助功能（原型已实现）

参考：Apple 要求打开"减弱动态效果"时把动画减到最少或去掉，可以用淡入淡出代替滑动、弹跳；watchOS 本身也尽量少用自动滚动、闪烁和移动；每个关键流程都要在开着 VoiceOver 和减弱动态效果时走一遍（[HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[App Store 减弱动态效果评估标准](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/reduced-motion-evaluation-criteria)、[WWDC21 10223](https://wwdcnotes.com/documentation/wwdc21-10223-create-accessible-experiences-for-watchos/)）。

- **减弱动态效果**：宠物停在一个静止姿势（动作还会换姿势，比如开心、犯困）；演出不晃、不闪、不飞光球，淡入后直接停在结果卡；"！"不闪；被摸时不转圈。跟随系统设置，原型里也能手动打开。
- **VoiceOver**：每个宠物图都有朗读文字，例如"火系成熟体·飞行，史诗，很开心"；手表上的好友行是可聚焦的按钮（"跟阿跑切磋"）。
- **颜色不是唯一信息**：属性药丸都带文字，稀有度用星数 + 文字，不只靠颜色。

## 5. 美术规范

> 画风已从像素改成赛璐璐卡通插画（决策第 61 条）。下面保留仍然适用的通用经验，尺寸和文件格式等有 Mac、选好动画方案后再定。

**参考：** 角色画的通用经验：
- 先过**剪影测试**：涂成纯黑还能认出来；
- 眼睛要跟身体有足够反差；手表屏幕小，喜怒哀乐主要靠眼睛和嘴；
- 头大身小，给眼睛留空间；
- 待机动画 2–3 个状态就够，弹跳用"压扁 → 拉伸 → 还原"。

**规则：**
- **尺寸**：定稿按大图交付（矢量或至少 1024px 的分层 PNG），在手表上 40px、64px 和主屏三个尺寸都要检查能不能认出。可以用 `apps/web/workbench.html` 叠图检查。
- **配色**：每只 3–4 个主色；属性主色固定（草绿、水蓝、火橙……），闪光变种只换配色。
- **剪影**：每个成熟体的剪影都要能一眼区分（飞行有翅膀、战斗有拳头、地面背上有岩刺、龙有角和尾巴）。
- **每只宠物每个形态要画的帧**：

| 动作 | 帧数 | 说明 |
|---|---|---|
| 待机 | 4 | 呼吸、跳一下（压扁 / 拉伸） |
| 眨眼 | 2 | 叠在待机上 |
| 开心 | 4 | 被摸、收服、打赢时 |
| 犯困 | 2 | 睡眠少时，点头 |
| 无聊 | 2 | 趴下 |
| 说话 | 2 | 张嘴、闭嘴 |
| 攻击 / 受击 | 3 / 2 | 战斗回放用 |
| 睡觉 | 2 | 冬眠、常亮模式 |
| 剪影 | 1 | 进化演出、图鉴未收服 |

- **文件规范**：命名 `{物种}_{阶段}_{形态}`，例如 `fire_adult_flying`。动画用骨骼动画工具（如 Rive）还是逐帧图，等验证过 watchOS 上的支持再定；网页原型和以后的 iPhone / 手表 App 读同一套导出文件。
- AI 出的图只当概念，正式图由插画师定稿，再过一遍剪影测试和配色检查。

## 探险：运动完，它出门（2026-11-21）

**参考**：Finch 的小鸟每天去冒险、回来讲故事。让运动有画面，而不只是一个数字。

| 规则 | 说明 |
|---|---|
| 触发 | 当天有一次 ≥ 10 分钟的运动记录保存进健康数据 |
| 出发 | 下次抬腕时，宠物先欢呼（已有），再说"今晚我去风之丘探险，明早回来！" |
| 去哪 | 按运动类型：跑步 / 走路 → 风之丘，骑行 → 回声峡谷，游泳 → 月光湖，力量 → 岩石营地，间歇 / 高强度 → 雷云山，瑜伽 / 拉伸 → 静谧林 |
| 回来 | 第二天早晨卡片里，**这一天的小惊喜换成"探险回来了"**：一张明信片（地点插画 + 宠物一句话）+ 一件那个地点的收藏品 |
| 收藏品档次 | 按运动时长分三档：≥ 10 / ≥ 30 / ≥ 60 分钟，越久越稀有；60 分钟封顶，不鼓励过度运动 |
| 次数 | 每天最多一次，多次运动按最长的一次算 |
| 收集 | 收藏册按地点分页；每个地点集齐解锁一个表盘主题或称号 |
| 没运动 | 不出门，小惊喜照常从原来的池子里抽，不扣任何东西 |

- 晚上出门、早上回来：白天宠物一直在表上陪你，不会"不在家"。
- 不给战斗力，只是收集和故事。
- 跟原来的"捡到小东西"合并：没运动的日子仍可能捡到普通收藏品，探险带回的是各地点专属的。
