# 10 技术架构：手表、手机、服务器、官网

> 相关：[08 服务器](08-服务器.md) · [06 MVP 与付费](06-MVP与付费.md) · [07 打磨规范](07-打磨规范.md) · [决策记录](../DECISIONS.md)（第 67 条）

## 总览

```
                ┌──────────── 官网 (Astro, Cloudflare Pages) ────────────┐
                │ 落地页 · 候补名单 · 隐私政策 · 条款 · 支持 · 分享/邀请链接 │
                └──────────────────────────┬─────────────────────────────┘
                                           │ 同一个域名、同一个 Cloudflare 账号
 ┌─ 手表 App (SwiftUI) ─┐   手表通信    ┌─ 手机 App (SwiftUI) ─┐   HTTPS   ┌─ 服务器 (Cloudflare Workers) ─┐
 │ 抬腕看宠物、3 页翻页 │ ◀──────────▶ │ 读 HealthKit、上传    │ ────────▶ │ packages/game + engine 结算     │
 │ 小组件、通知、蓄力   │              │ 图鉴、回放、来信、付费 │ ◀──────── │ D1 数据库 · R2 图片 · 推送      │
 └──────────────────────┘              └───────────────────────┘           └─────────────────────────────────┘
```

**原则：规则只有一份。** 成长、遭遇、对战、早晨卡片全部由服务器上的 TypeScript 代码算（就是现在的 `packages/game`、`packages/engine`），手机和手表只负责读数据、上传、显示。网页原型、服务器、App 看到的结果完全一样，改数值不用发版。

## 每一端做什么

| 端 | 职责 | 技术 | 最低系统 |
|---|---|---|---|
| 服务器 | 按天结算、账号、存档、好友快照、周 Boss、订阅校验、推送、图片下发、AI 说话 | Cloudflare Workers（TypeScript，路由用 Hono）+ D1 + R2 | — |
| 手机 App | 首次打开（选蛋、授权、孵化）、读 HealthKit 并上传、早晨卡片完整版、图鉴、进化树、对战回放、来信、好友、分享图、付费墙、数据页、设置 | SwiftUI、HealthKit、StoreKit 2、Sign in with Apple、WatchConnectivity | iOS 17 |
| 手表 App | 宠物页 / 今天 / 对战 三页、早晨卡片精简版、运动后欢呼、好友切磋的蓄力点击、表盘小组件和智能叠放、通知 | SwiftUI、WidgetKit、WatchConnectivity | watchOS 10（表冠竖向翻页，见决策第 46 条） |
| 官网 | 宣传和候补名单、隐私政策（App Store 和 HealthKit 审核必需）、用户条款、支持页、好友邀请和分享落地页 | Astro 静态站 + Cloudflare Pages；表单和动态页由同一个 Worker 处理 | — |

## 手机和手表：同一个 Xcode 项目

```
apps/apple/
  Pulseling.xcodeproj
  Shared/          Swift 包：数据模型、接口客户端、图片缓存、动画播放器
  iOS/             手机 App
  Watch/           手表 App
  Widgets/         手表小组件（WidgetKit）
```

- **数据模型从 TypeScript 生成**：服务器接口的类型写在 TS 里，用工具（如 quicktype 或 OpenAPI 生成器）生成 Swift 的 `Codable` 结构，避免两边手抄字段。
- **健康数据由手机上传**：手表的数据会同步进手机的 HealthKit，手机统一读、算一天一行的汇总、上传。手机端注册 HealthKit 后台推送，有新数据时被唤醒（延迟要真机测，见 [PROTOTYPE](../PROTOTYPE.md) 已知问题）。
- **手表拿状态**：优先由手机通过 WatchConnectivity 推过来；手机不在身边时，手表自己联网向服务器取（手表能走 Wi-Fi 或蜂窝）。
- **小组件**：手表 App 和小组件通过 App Group 共享一份最新状态，小组件按时间线刷新（宠物作息、睡觉 / 醒来）。
- **动画**：序列帧（每个动作一组图），SwiftUI 的 `TimelineView` 逐帧播放；减弱动态效果时显示静止姿势（见第 50 条）。
- **离线兜底（第二步再做）**：把 `packages/game` 打包成一个 JS 文件，放进 App 用系统自带的 JavaScriptCore 跑，没网时先出早晨卡片，联网后以服务器为准。

## 服务器

沿用 [08](08-服务器.md) 的设计（客户端上传触发结算、种子 = 用户 ID + 日期、幂等），技术栈定为 **Cloudflare Workers + D1 + R2**。

| 模块 | 做法 |
|---|---|
| 账号 | 首次打开生成匿名账号；开试用时用 Sign in with Apple 绑定，Worker 里用 `jose` 验 Apple 的 token |
| 结算 | `POST /days`：收前一天汇总 → 跑 `liveDay` → 存状态 → 返回早晨卡片数据 |
| 对战 | 周 Boss、好友切磋都在服务器算，返回种子和结果，客户端按种子播放回放 |
| 订阅 | StoreKit 2 的交易凭证发到服务器，服务器用 App Store Server API 校验；订阅变化用 App Store Server Notifications 回调 |
| 推送 | Worker 直连 APNs，先往沙盒发一条验证（[08](08-服务器.md) 的待验证项） |
| 图片 | 放在 R2，带版本号的清单 `manifest.json`；每张图两套：手机用的大图、手表单独重画的小图（见 [09](09-美术生图提示词.md) 手表小图一节） |
| AI | Worker 调你自己的 new-api 网关；宠物说的话先在服务器生成好、跟早晨卡片一起返回 |

## 官网

| 页面 | 作用 | 什么时候要 |
|---|---|---|
| `/` 落地页 | 一句话卖点、15 秒视频、三只初始精灵、候补名单表单 | 现在（先测需求） |
| `/privacy` 隐私政策 | 写清 HealthKit 数据只存一天一行汇总、不卖、不做广告（见 [03](03-健康数据.md)） | 提交审核前必须有 |
| `/terms` 用户条款、`/support` 支持 | 审核和订阅需要 | 提交审核前 |
| `/f/<好友码>` 邀请链接 | 装了 App 就直接打开 App 加好友，没装就去 App Store | 好友系统上线时 |
| `/p/<宠物>` 分享页 | 分享图的网页版，带社交平台预览图（Worker 实时生成） | 分享功能上线时 |
| `/.well-known/apple-app-site-association` | 让上面的链接能直接打开 App（Universal Links） | 好友系统上线时 |

候补名单的邮箱存在 D1，只用于上线通知。

## 仓库结构（加完之后）

```
packages/engine    数值规则（已有）
packages/game      一个玩家的状态和每天发生什么（已有，服务器直接用）
apps/sim           批量模拟（已有）
apps/web           网页原型（已有）
apps/server        Cloudflare Worker（新）
apps/site          官网 Astro（新）
apps/apple         Xcode 项目：手机 + 手表 + 小组件（有 Mac 后）
```

## 开发顺序

| 阶段 | 内容 | 需要 Mac 吗 |
|---|---|---|
| 1 | 官网 v1：落地页、候补名单、隐私政策 | 否 |
| 2 | 服务器：搬入 `packages/game`、匿名账号、按天结算、存档；验证 Apple 登录验签和 APNs 推送 | 否 |
| 2' | 美术：按 [09](09-美术生图提示词.md) 批量出图 → 定稿（和 1、2 同时进行） | 否 |
| 3 | 接 AI（宠物说话、周信），在网页原型里先试 | 否 |
| 4 | 手机 App：首次打开、HealthKit 上传、早晨卡片、图鉴、付费 | 是 |
| 5 | 手表 App：三页、小组件、通知、蓄力 | 是，且要真机 |
| 6 | TestFlight 给朋友试用 → 提交审核 | 是 |

没 Mac 时的过渡方案见 [HANDOFF](../HANDOFF.md)"技术方案"一节（云端 Mac、GitHub Actions 的 macOS 机器）。
